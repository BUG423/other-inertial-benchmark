# Exact final-test alias reuse: accepted CPU scope

`eval_alias_reuse` defaults to `false`. Setting the benchmark plan's boolean field to `true` enables CPU-only reuse within one benchmark item's final-test aliases. The policy is part of scientific run identity; switching it cannot silently reuse completed outputs under a different policy. The default path retains its existing plan and identity. There is no persistent or cross-run cache.

Reuse requires the same ordered native sequences, actual input/target arrays, clock and masks, checkpoint bytes, model state, input specification, loss epoch/phase, batching, sampling and requested outputs. Each alias still constructs a fresh Validator/Predictor and loads its checkpoint, preserving ordinary constructor RNG consumption. The source must complete ordinary evaluation and save every requested artifact before reuse. Each alias saves its own complete metrics, predictions, requested plots and provenance. Source efficiency timing is never copied, and RNG state is never restored.

The opt-in path admits only source-bound, known stateless CPU model implementations. Unknown model or Torch metadata, changed source/runtime methods, mutable or stochastic evaluation, hooks, callbacks, efficiency requests, changed model/RNG state, incomplete or tampered artifacts, and the session memory bound cause ordinary evaluation or prevent source commitment. Every active TorchFunctionMode, TorchDispatchMode, infrastructure mode and pre-dispatch mode is refused, including transparent external modes. Unavailable or unqualified inspection APIs also fall back; these checks do not run on the default path. Mode checks occur at qualification, lookup and commitment, and a refused lookup invalidates the attempt so that it cannot later commit a mode-affected source. CUDA reuse remains refused.

On 2026-10-14, root accepted **44 actual CPU passes**, with zero failures, errors or skips: 42 scientific/refusal nodes (the previous 33 plus nine mode/observer guards) and two real SubT-MRS/default-width nodes. Collection, per-node setup/call/teardown reports and JUnit agree. All ran from the frozen 454-file engineering source below using Torch `2.12.1+cu130`, two Torch/OMP threads and one interop thread; CUDA stayed uninitialized. The CPU receipt records 169.4226 seconds and release of the supplemental exclusive lease. The ten protected source snapshots, 70 native registry/metadata/split entries, 11 staging entries and 13 policy/seed/capacity/prior-evidence entries match before and after execution, including terminal guards. Earlier failures, the diagnostic, V3 and the earlier real two-node proof remain preserved.

The six synthetic/reduced-width positive cases exercise registered NIO LieEvents RoNIN/TLIO, RoNIN ResNet and IMUNet. They compare exact numerical arrays, raw outputs/sigma, masks, loss, metrics, calibration, configuration, complete artifact provenance and post-constructor CPU RNG. A passive `sys.setprofile` observer counts the original `torch.conv1d`/`torch.conv2d` C API calls without installing Torch modes, model hooks or API wrappers; it refuses to replace an existing Python profiler. Four ordinary alias predictions versus one reused source gave a **4:1 source API call ratio** in all six cases. These are API counts, not backend kernel counts or a measured fourfold wall-time/GPU speedup.

The real probe uses existing completed RIDI-trained checkpoints (seed `1735231569`, loss epoch `4`) for `nio_lie_events_ronin_3d` and `nio_lie_events_tlio`, with default widths (`group_sizes=[2,2,2,2]`, `base_plane=64`, `trans_planes=128`, `fc_dim=512`). It takes the first admissible 221 frames (1.1 seconds) of the canonical first SubT-MRS test sequence, `Final_Challenge_UGV1_infrastructure_corridor_1`, selected before model outputs. Original arrays, axes, masks and reference attributes are retained without interpolation/resampling; the clock offset is recorded. The reference orientation and initial velocity are privileged inputs. Its map-constrained visual/LiDAR/IMU fusion reference includes the input IMU. Both models give exact XYZ results and XY metrics computed from the **same XYZ predictions**, with exact raw uncertainty/loss/calibration, artifacts and RNG; API counts are 84/21 and 88/22 respectively.

This acceptance covers finite engineering equivalence. It does not establish paper accuracy, a full 28-sequence SubT result, CUDA qualification, or a performance improvement for the ongoing frozen 425-file/2067-cell formal experiment. That experiment and its completed outputs are unchanged; this acceptance does not mark the full matrix complete or relabel results.
